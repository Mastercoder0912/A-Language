PART 6A: Main Entry Point (main.c)
--------

Create command-line interface:

main(int argc, char* argv[]):
  - Check argc >= 2 (program name + .a file)
  - Read file path from argv[1]
  - Read file into buffer
  - Create lexer with source
  - Create parser with lexer
  - Call parse_program()
  - Check for parse errors (exit if found)
  - Create interpreter with program
  - Call interpreter_run()
  - Check for runtime errors (exit if found)
  - Free all structures
  - Exit with status 0

Error handling:
  - File not found: print error, exit 1
  - Lexer error: print token info, line/column, exit 1
  - Parser error: print error, expected token, line/column, exit 1
  - Runtime error: print error, current statement context, exit 1

Usage example:
  `sac program.a`
  `sac tests/arithmetic.a`


PART 6B: Testing Progression
--------

Build test files incrementally. Create these test files:

test1_arithmetic.a:
  ```
  int x = 5
  int y = 3
  print(x + y)
  print(x * y)
  print(x - y)
  ```
  Expected output:
  ```
  8
  15
  2
  ```

test2_variables.a:
  ```
  int x = 10
  string name = "Alice"
  boolean flag = True
  print(x)
  print(name)
  print(flag)
  ```

test3_control_flow.a:
  ```
  int x = 15
  if (x > 10) {
      print("Greater")
  }
  else {
      print("Not greater")
  }
  ```

test4_loops.a:
  ```
  loop (3) -> i {
      print(i)
  }
  ```

test5_functions.a:
  ```
  function add(a, b) {
      return a + b
  }
  print(add(5, 3))
  ```

test6_structs.a:
  ```
  struct Point {
      int x;
      int y;
  }
  Point p = Point(4, 5)
  print(p.x)
  print(p.y)
  ```

test7_classes.a:
  ```
  class Dog {
      private string name
      function Dog() {
          name = "Buddy"
      }
      function .getName() {
          return name
      }
  }
  Dog d = Dog()
  print(d.getName())
  ```

test8_collections.a:
  ```
  list nums = []
  nums.fill(0)
  nums[0] = 42
  print(nums[0])
  ```

Run each test:
  `sac test1_arithmetic.a`
  Compare output to expected
  Fix any bugs
  Move to next test


PART 6C: Debugging Strategy
--------

When a test fails:
  1. Check lexer output:
     - Print all tokens with `token_print()`
     - Verify token sequence matches language syntax
  
  2. Check parser output:
     - Print AST structure
     - Verify nesting and operators
  
  3. Check interpreter state:
     - Add debug prints to env_define(), env_get()
     - Print values as they're assigned
     - Print function calls as they execute
  
  4. Check specific operation:
     - For arithmetic: verify eval_binary_op() operator handling
     - For functions: verify parameter binding and scope
     - For objects: verify instance creation and field access

Common issues:
  - Operator precedence wrong: check parse_multiplicative() called before parse_additive()
  - Scope wrong: check env_push_scope()/pop_scope() called at block boundaries
  - Type mismatch: check value_to_string() handles all types
  - Memory leak: check value_free() called on unused values
